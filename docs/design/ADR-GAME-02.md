# ADR-GAME-02 · 服务端权威 tick，前端只做呈现

- 状态：已接受
- 日期：2026-11-12
- 关联：计划报告 §6 ADR-02、方案书 §5.1

## 背景

现状是"前端回放"：`app.js` 的 `S.t` 对**已算好的关键帧**做插值，倍速只影响"看"不影响"算"。
要做实时游戏，必须决定时钟归谁：前端本地推进（易掉帧、易漂移），还是服务端推进（单一时钟）。

## 决策

**仿真逻辑全部在本地 Python（`console/server.py` 进程内的 tick 线程），前端只发命令、收状态。**

- 倍速 = 服务端 `speed ∈ {0,1,2,4,8}` 参数，不是前端插值加速。
- 暂停 = 服务端 `paused=true`，`tick_i` 停止增长。
- 状态推送先用 600 ms 轮询（沿用 `pollJob` 的做法规避 SSE 复杂度），SSE 作为可选优化。

## 理由

1. **离线约束**：交付是 PyInstaller 打的 exe，无网络、无 CDN，逻辑无法放在外部服务。
2. **单一权威时钟**：两套时间逻辑必然漂移，违反项目既有的"一份数据多个消费者"铁律。
3. **确定性**：同一 `(seed, 命令流)` 无论前台是否卡顿，服务端 tick 序列完全一致——这是 `CMD_OK` 的前提。

## 后果

- 前端 `app.js` 的 `setPlaying` / 倍速按钮必须改为发 `/api/game/pause`、`/api/game/speed`。
- `viewer3d.js` 渲染层不需要改：只要把 `sampler` 换成"读服务端快照"的实现即可（`update(t,sel,sampler)` 已是注入式）。
- 服务端 tick 线程与 HTTP 线程共享 `Simulation`，必须加会话锁（否则命令丢失/状态撕裂）。

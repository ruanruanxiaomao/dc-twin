# ADR-GAME-01 · 增量包裹而非重写

- 状态：已接受
- 日期：2026-11-12
- 关联：`模拟运营游戏改造计划报告.md` §6 ADR-01、上游 `docs/DC_MASTER_PLAN.md`

## 背景

`dc_project` 已有 40 项硬验收（A1–A40）、65 个 pytest、17 个负测试、KPI golden、逐字节 clean-room、
事件溯源账本。这些不是"示例代码"，而是已经审计过的资产。把"数字孪生"改造成"模拟运营游戏"时，
最诱人的做法是另起一个 `game/` 包重写仿真——那样能自由设计，但会同时丢掉上面全部安全网。

## 决策

采用 **Strangler Fig（绞杀者）增量包裹**：保留确定性引擎与全部验收链，在外层新增游戏能力。

- **保留**：`scripts/sim_engine.py` 的确定性核心、`scripts/ledger.py` 事件溯源、四层 JSON 配置、A1–A40。
- **新增**：可外驱 `step()`、玩家命令队列、服务端实时循环、运行中快照、实时经济、关卡目标、存读档。
- **降级**：Blender 45 步渲染链从"主交付"降为可选"过场动画导出"，不阻塞游戏循环。

## 后果

- **正面**：任何一步都能用既有验收链证伪；失败可回退；批跑模式永久保留为"复盘/重放"。
- **负面**：引擎必须同时满足"批跑逐字节不变"与"可中途介入"两个约束，`run()`→`step()` 的
  重构容错空间极小（见 ADR-GAME-03 与 `scripts/step_baseline.py`）。
- **强制**：批跑产物逐字节不变是硬门（`STEP_OK`），不是"尽量"。

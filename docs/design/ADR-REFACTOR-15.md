# ADR-REFACTOR-15 · 面积真的变成库容了：整场重排，不只是室内

- 状态：已实施（R8.7 第一部分）
- 日期：2026-11-13
- 关联：ADR-REFACTOR-14（R8.6 面积只传导到壳体/导航格）、`scripts/layout_solver.py`、
  `scripts/check_area_param.py`

## 背景

R8.6 的诚实结论是："填满进深"当场撞出 **1022 处** L3/L4/L6。当时的解释是
"月台/功能区是绝对坐标，不随面积重排，所以面积进库容需要 D10b 求解器"。

这一轮把那个求解器做了。关键不是算法，而是**先搞清楚谁锚在哪儿**。

## 决策一：按锚定关系切分进深，不做搜索

布局里三类东西的锚定关系天然不同：

| 对象 | 锚 | 理由 |
|---|---|---|
| 月台 | **南墙** | 卸货口对着场外，挪了就不是月台 |
| 功能区（收货暂存/包装/分拣/充电位） | **后墙** | 要靠墙摆，但"哪面墙"随厂房走 |
| 货架 | **中间剩下的进深** | 它本来就没有锚，是填充物 |

于是面积一变，正确动作只有两步：功能带整体平移到新后墙内侧；货架组的进深预算
改成"**功能带前沿** − 起点 − 余量"（原来是"后墙 − 起点 − 1 m"）。

一行减法加一次平移，没有搜索、没有迭代、没有阈值调参。给定输入必然同一结果，
所以它可以被逐项证伪——这是它能进门的前提。

## 决策二：行数上限取三个值的最小

只看到功能带还不够。A 区在前排、C 区在后排，同一列；A 区若一路排到功能带前沿，
会把 C 区的地吃光。所以上限是三者取 min：

1. 功能带前沿 − 施工余量；
2. **同 x 列里起点更靠后的货架组**起点 − 余量（`sibling_zone_C@z=41`）；
3. 没有功能区时退回后墙。

`free_depth_for_group()` 的返回里必须写 `blocked_by`。R8.6 那 1022 条之所以难读，
就是因为校验层只报"重叠"，不报"你在跟谁抢地方"。

## 决策三：zone 框不参与碰撞

zone（A/B/C/D 的彩色矩形）是渲染用的，不参与 L3 判定。让行数去服从"颜色框"
而不服从真实障碍，等于把审美写进约束。所以求解模式下，行数只认真实障碍；
zone 若被货架穿过，那是数据标注该跟上，不是几何该让步。

## 三个自己踩的坑（都留了测试）

1. **常量后沿余量会改四个仓的布局。** 第一版用 `TAIL_GAP=3.0`（W 仓恰好是 3），
   结果把 F1/F2/F3 的功能区整体推后 3 m，前置仓当场 24 处 L4/L6。
   → 改成**显式基线** `wh.area_baseline.depth`；没有基线就 `shift=0` 不推断。
   *猜一个常量，等于给所有仓同时改布局。*

2. **"新进深 − 旧进深"不幂等。** 门会重跑，第二次又推 14 m，功能带跑到 90，
   所有断言失去意义。→ 改成"**目标位置 − 当前位置**"，后沿余量从基线反推
   （`基线进深 − 基线带前沿 − 带高`），所以各仓可以各不相同，且天然幂等。

3. **余量必须容得下访问点，充电位必须算进功能带。** 每排货架后侧也有一个 AP，
   最后一排贴到上限时它的后侧 AP 就落在通道里没地方站（3 个 SHELF AP 报 L6）；
   充电位的 AP 在 `start + ap_dz`，不把充电位算进带里，货架会排到它跟前
   （1 个 `W-CHG-06` 报 L6）。两条都修完，1022 → 1；整场重排后 → 0。

## 结果

放大 100×70 → 120×84（`depth_budget:"from_size"` + `area_reflow:true` + 基线 70）：

| 指标 | 未求解 | 求解后 |
|---|---|---|
| issue 总数 | 1022 | **0** |
| L3（重叠） | 27 | **0** |
| L4（AP 落进实体） | 345 | **0** |
| L6（AP 不可达） | 650 | **0** |
| 全站库位 | 441 | **525（+84）** |

功能带平移 +14 m（62..69 → 76..83），货架组预算 A/B 27 m、C/D 33.5 m。

## 残留清零：整场重排，不只是室内（R8.8）

上一版剩 1 条 `W-CHG-06 AP not walkable`。原因不是"忘了移装备"，而是**把问题看小了**：

`site` 总进深 114 m，W 占 0..70，场地占 70..90（叉车 z=72、卡车 z=82、道路 68..92），
前置仓 F1/F2/F3 在 90..110。W 长到 84 以后，20 m 的场地只剩 6 m —— 卡车（12 m）
根本放不下，只能被迫停在 82，正好压在充电位访问点上。

所以正确的模型是：**z 轴是一条连续的场地关系，建筑向北生长，北侧的一切都要跟着北移。**

```
建筑 +14  →  功能带 62..69 → 76..83
          →  场地道路/装卸位/叉车位 +14（叉车 72→86，卡车 82→96）
          →  前置仓 F1/F2/F3  origin.z 90→104
          →  site 进深 114→128（由 max_z+4 自动长大，不手改）
```

判据是"是否在旧北墙以北"：`origin.z >= 旧北墙`，而旧北墙 = `新 origin.z + 新进深 - shift`。
这条判据对四个仓通用，不需要给每个仓配常量——上一版正是给 W 配了个常量就把
F1/F2/F3 一起推错了。

放大后的整场实测：site 114→128、W 84 深 / 220 架、前置仓 z=104、叉车 86、卡车 96、
功能带 76..83、**库位 441→525，issue 0，exit 0，写盘成功**。

## 门的两次收紧（`SOLVE_RESIDUAL_MAX` 6 → 0）

- `AREA_SOLVE_OK` 允许残留但必须逐条归因、上限原来是 6。现在收紧到 **0**：
  留一个上限等于给同一类问题永久开一道口子，而它已经被真正解决了。
- 新增 `AREA_DELIVER_OK`：放大布局必须 **0 issue + exit 0 + 写盘成功 + site 与前置仓
  真的长大了**。这是"面积→库容"这句话的兑现口径——之前 `AREA_SOLVE_OK` 只能证明
  "算得出来"，那份布局是被校验拒绝的，数字漂亮但交付不了。
- **归因从子串匹配改成因果判定**（`_explain_residual`）：旧版只要 message 含
  `SHELF`/`CHG` 就归因"室外装备"，那是个掩蔽口，任何新的 SHELF L6 都会被吞掉。
  现在要求：能定位到真实访问点 → 该点真的落在某台叉车/卡车的 footprint+AGV 半径内 →
  文案里带设备 id 与坐标。三条缺一条就判红。自检加了 `residual_attribution_causal`
  反例（编一条离装备很远的 SHELF L6，必须被抓）。

自检 8 条反例全部命中：`no_change_detected`、`silent_shrink`、`silent_fill`、
`solve_without_shift`、`solve_l3_not_cleared`、`solve_no_capacity`、`deliver_rejected`、
`residual_attribution_causal`。

## 门（`AREA_SOLVE_OK`，三条一起断言）

1. L3 / L4 必须为 **0**（结构冲突清零，不是"挪了个地方"）；
2. issue 总量必须从 1022 降 ≥ 99%（证明真在解，不是换名字）；
3. 库位必须**严格增加**（否则"求解成功"只是把越界换成了不增长）。

外加：`area_reflow` 记录必须存在且 `shift≠0`（证明面积真的传导了）。

自检 6 条反例全部命中：`no_change_detected`、`silent_shrink`、`silent_fill`、
`solve_without_shift`、`solve_l3_not_cleared`、`solve_no_capacity`。

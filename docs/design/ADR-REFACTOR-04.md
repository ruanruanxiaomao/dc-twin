# ADR-REFACTOR-04 · 资料 5 处口径 bug：修正、负对照、以及与方案书的一处差异

- 状态：已采纳（R0，2026-11-13）
- 相关：§5.1；`scripts/capacity_model.py`；`scripts/check_capacity_spec.py`

## 背景

教学工具（`评价公式说明.html` + 布局工具）自带 5 处口径错误。项目的纪律是
**先修口径、再用负测试钉住**，而不是"资料这么写我就这么抄"。

| # | 资料现状 | 修正 |
|---|---|---|
| B1 | `ρ=(in+out)/C`，分母是**复合**能力（1 复合 = 1 存 + 1 取） | `ρ=(in+out)/(2C)` |
| B2 | `t=(D̄/v)·d_f`，而 `D̄=(L_a/2)·d_f` 已含 d_f → 实际 d_f² | `t=D̄/v`，与堆垛机同口径 |
| B3 | 只有叉车分支查 `levelH·level>maxHeight`，堆垛机漏检 | 所有设备类型统一查 |
| B4 | `goods.mass` 与 `cell.loadCap` 只存不用，无承载校验 | 单托总重 ≤ min(货架载, 货位额定, 设备载荷) |
| B5 | `nDepth=1` 硬编码（input disabled max=1） | 解锁 nDepth，与机理联动 |

## 决策

1. **两版公式同时写在 `capacity_model.py` 里**，用 `FIX` / `LEGACY` 两组开关切换。
   只在代码里写"对的版本"，无法证明"错的那版真的会更错"；两版并排，负对照才有意义。
2. `--self-test` 逐条要求：修正版与资料原式**结果不同**，且差异方向符合物理
   （原式把负荷高估一倍、把距离算成平方、把堆垛机高层漏检、把超载放行、把深位压成一）。
3. **配置里也保留开关**（`equipment_spec.time_model.load_rate_divisor` 等），
   这样"有人把口径改回资料原式"会被 `check_capacity_spec.py` 当场抓到，
   而不是等某天发现库容数字不对再回溯。
4. **B1 的能力语义显式钉住**：`C_a` 的单位是「复合次/h」，所以
   `in=out=C_a` 时恰好饱和（ρ=1.0），`in=out=C_a/2` 时 ρ=0.5。

## 与方案书 §12.1 的一处口径差异（必须记下来）

方案书 B1 负对照写的是「构造 in=out=C_a 的巷道，ρ_a 须=0.5（非 1.0）」。
这句话只有在 **C_a 是「单次指令能力」** 时成立；而同一份文档的 C.7 把
`C_a = Σ Q_m·n_e`（`Q_m = 3600/T_c`，即**复合**能力）定义清楚了。

两者差一个系数。本项目按 C.7 的定义实现（C_a = 复合次/h），于是：

```
in=out=C_a      → ρ = 1.0（刚好饱和）
in=out=C_a/2    → ρ = 0.5
legacy 同输入   → 恰好是修正版的 2 倍
```

**被守的性质没有变**：分母必须 ×2，否则负荷被高估约一倍，玩家会被逼着多买设备。
`tests/unit/test_capacity_model.py::test_b1_capacity_semantics_are_pinned` 两条都断言了，
所以无论是"按复合能力"还是"按单次能力"读这份配置，数字都不会被误用。

## 后果

- 正向：五条负对照都能失败；口径一旦被改回资料原式，`check_capacity_spec.py` 与
  pytest 双重报警。
- 负向：`LEGACY` 这组值会长期留在代码里（作为"反面教材"）。这是有意的——
  删掉它就再也证明不了修正在起作用。
- 未做：B1–B5 进主链是 R4 的事；R0 只保证公式与对照成立，不改变任何既有产物。

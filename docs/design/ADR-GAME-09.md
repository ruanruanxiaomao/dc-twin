# ADR-GAME-09 · 库存层的三个决策（P6a）

- 状态：已接受（P6a-0 定稿，P6a-1 起执行）
- 日期：2026-11-12
- 关联：`模拟运营游戏_P6a库存层方案书.md` §6 / §5.4 / §8；ADR-GAME-04（经济单一事实来源）、ADR-GAME-05（快照双轨）

## 决策一 · 采购成本不进 P&L，只作资金占用（**修正了方案书的理由**）

**决策**：`STOCK_REPLENISH_ARRIVED` 不记任何成本分录；`unit_cost × qty` 只汇成
`inventory_value` 展示在资产侧。

**方案书给的理由是错的，必须改**：原文写"`per_order` 已是市场售价，再记
`unit_cost×qty` 会与售价重复抵扣毛利"。售价是**收入**，采购成本是**成本**，
两者在利润表的不同侧，不存在重复抵扣——真按原始理由写进 ADR，将来一定有人
"发现"这不是重复计账，然后把 COGS 加上去，把平衡打崩。

**真实理由有两条**：

1. **现有营收口径是"覆盖全部成本并留利"的打包价，不是"售价 + 另行核算货物成本"。**
   实测：`cost_spec` 演示单价下 8 个场景全部亏损（1 小时营收 ¥193 vs 固定成本 ¥751），
   因此游戏侧用 `tariff_multiplier = 5.0` 把营收拉到市场价（ADR-GAME-04 的倍率说明）。
   这个 ×5 是在**没有 COGS** 的前提下标定的；再叠一层货物成本，等于把利润打回负数，
   必须整条价格体系重新标定。
2. **项目里已有一笔"每单耗材"`consumables_per_order`**，它承担的就是单笔可变物料成本的角色。
   再加 COGS，即便会计上不算重复，玩家看到的成本结构也会重复表达同一件事。

**后果**：要做真实毛利，必须单独立 ADR + 重标 `tariff_multiplier` + 重冻 golden，
三件事一起做；不许只加一条分录。

## 决策二 · `SNAPSHOT_SCHEMA` 升 2.0，旧存档显式拒绝

**决策**：`Simulation.SNAPSHOT_SCHEMA = "2.0"`；`restore` 读到 `1.0` 直接 raise，
错误信息写明"旧存档无库存账，不能续玩"。`game_save` 的信封 `SCHEMA` 同步升 2.0，
让旧文件在**读档入口**就被拒，而不是深入 `restore` 才报版本不符。

**理由**：不静默补空账。补空账的后果是：读档成功、跑几十个 tick 后库存对不上，
而那时已经分不清是"档案旧"还是"引擎漏状态"（R4 的典型形态）。

**代价**：P6a 之前的存档全部失效。当前存档只有开发期的测试槽（`saves/` 已被
`.gitignore` 排除），无用户数据，可接受。

## 决策三 · 一次 v2 重冻 + 双基准并存

**决策**：v1 原件永久保留；新增 `step_baseline_v2.json` / `kpi_baseline_v2.json`；
`--check` 默认 v2，`--check=v1` 显式"预期不同"；`out/refreeze_report.json` 逐事件类型
给出计数差。不搞 v2a/v2b 中间态。

**理由**：多次中间冻结会让"哪一次改了什么"重新变成考古。一次冻结 + 逐事件归因，
delta 才能逐条落到机制上。

**强制**：`REFREEZE_OK` 判据里包含"`--check=v1` 必须**红**"。若 v1 意外变绿，
说明库存改动根本没进事件流——那本身是 bug，门必须判红（方案书 §8.3 已写明）。

## 决策四（执行方补充）· SKU 由库位反查，不给订单加字段

**决策**：库位到 SKU 是**一对一**映射（`data/inventory_slotting.json` 覆盖全部 392 个
SHELF 库位，无空位）；订单的 SKU 由 `pick_loc` 反查得到，**不在 `new_order()` 里抽样**。
查不到 → raise。

**理由**：`new_order()` 每多一次 `rng.next()` 都会改变后续所有随机流——需求到达、
库位选择、优先级全都跟着变。那会让 v2 的 delta 无法归因（"变了什么"和"为什么变"
混在一起）。由库位反查是零随机、零字段变更，而且 CSV 适配器（无 sku 字段）不需要改。

**代价**：一个库位只能放一个 SKU。P6a 不模拟混放/多批次共用库位——本来也在 P6b。

**配套**：`slotting.json` 有 152 个 EMPTY 库位，若留空，反查就会 raise。所以在
`gen_inventory.py` 里把空位按速度序补给 A 类 SKU 作溢出储位，让"任何 SHELF 库位都有
SKU"成为**数据层不变量**（`tests/unit/test_inventory.py` 钉住）。

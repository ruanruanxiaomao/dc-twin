# ADR-GAME-05 · 存档双轨：快照续玩 + 事件重放

- 状态：已接受
- 日期：2026-11-12
- 关联：计划报告 §6 ADR-05、方案书 §8.1

## 背景

`_state()`（`sim_engine.py:1513`）名叫 state，实质是**终态摘要**：只有机器人终态、队列深度、
封门集合，用于 KPI 对账。它缺 RNG 内部状态、当前 tick、队列内容、在途路线、dwell 计时器、
故障排程进度——**不可恢复续跑**。而项目已有两个存档友好资产：确定性 `Mulberry32`
（`deepcopy` 即得等价独立流）与 append-only 事件日志。

## 决策

**双轨并存。**

- **快照轨**（续玩）：`snapshot()` / `restore()`，含全部可变状态（见方案书 §2.4.2）。
- **重放轨**（审计/复盘）：`(seed, 命令流, 场景)` → 重跑复现整局，用于审计与"复盘模式"。

`_state()` 保持原样不动（KPI 对账与 A 系列验收依赖它），新增独立的 `snapshot()`。

## 理由

1. 快照解决"续玩"（用户关掉再打开能接着玩），重放解决"可审计"（数字怎么来的可以重算出）。
2. 快照若只存"够用的一部分"，漂移会在若干 tick 后才显现，极难定位——所以字段必须**穷举**。
3. 双轨互为校验：`restore(snapshot())` 续跑必须与不中断跑逐字节一致（`SAVE_OK`），
   这个门同时证明了快照完备性。

## 后果

- `Robot` 必须新增 `serialize()/deserialize()`，覆盖 30+ 可变字段（模型常量由 `model` 重建，不入快照）。
- `EventLog` 的 `__init__` 是 `open(...,"w")`（截断）。restore 时必须**以 append 重开并恢复 `seq`**，
  否则已写事件被清空、后续 seq 从 1 重号（R11）。负测试：截断重开必须报错。
- 快照版本不符 / 缺字段 → `restore()` 必须失败（不许"尽力而为"地补默认值）。

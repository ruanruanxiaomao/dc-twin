# Data contracts

## 1. Layers

| Layer | Files | Owner |
|---|---|---|
| L1 inputs | `config/layout_spec.json`, `fleet_spec.json`, `demand_spec.json`, `config/scenarios/*.json`, `data/config.json` | human / `dc run --seed` |
| L2 derived | `data/layout.json`, `skus.json`, `events.jsonl`, `tasks.json`, `slotting.json`, `nav_grid.json`, `paths.jsonl`, `routes.json`, `cargo_state.json` | generated by `scripts/*.py` |
| L3 reports | `out/*_report.json`, `out/validate_report.json`, `out/CURRENT_STATUS.md` | generated by validators |
| L4 artifacts | `.blend`, `.glb`, `renders/*.png`, `anim_dc.mp4` | generated by Blender scripts |

Generated files are **not tracked by git** (except `out/CURRENT_STATUS.md`,
the single source of truth for current numbers). Rebuild with `dc run --scope full`.

## 2. Input schemas

`config/schemas/` holds four JSON Schemas: `layout_spec`, `fleet_spec`,
`demand_spec`, `scenario`. `spec_layout.py` enforces them (with `jsonschema`
when installed, otherwise a built-in required-field check) and runs the
L1–L12 geometric rules before writing `layout.json`.

Key invariants: layout 2D is `[x, z]`; Blender 3D is `(x, z, h)`, Z-up, metres;
glTF is Y-up. `AGV_RADIUS = 0.7296 m` is shared by `geometry.py`, the nav
grid, the planner and the validators.

## 3. Report envelope (sidecar, non-breaking)

The original report payloads are left unchanged. For each `out/<name>.json`
a sidecar `out/<name>.meta.json` carries:

```json
{
  "schema_version": "1.0",
  "kind": "traffic_report",
  "generated_at": "2026-11-08T11:00:00Z",
  "generator": {"name": "dc-twin", "version": "0.1.0", "git_commit": "...",
                 "python": "3.13", "blender": "5.2.3"},
  "inputs": [{"path": "config/layout_spec.json", "sha256": "..."}],
  "verdict": "PASS",
  "data_sha256": "..."
}
```

Consumers should read `schema_version` and reject incompatible reports instead
of silently rendering wrong numbers. `out/validate_report.json` is a **list** of
checks (legacy shape); its sidecar describes that explicitly.

## 4. Manifest & drift detection

`scripts/manifest.py` writes `out/manifest.json`: every artifact path, size and
SHA256; input hashes; tool versions; git commit; seed; UTC timestamp.
`dc validate --check` recomputes key reports and compares them with the
manifest, so CI can detect stale reports or derived-data drift.

## 5. Traceability

`out/traceability.md` maps `A1..A40 → test_id`. `out/CURRENT_STATUS.md` is
generated by `scripts/report_status.py` from the JSON reports — never edited
by hand. Scenario runs write `runs/<id>/<UTC-stamp>/{scenario.json, layout.json,
events.jsonl, kpi.json, assertions.json, manifest.json, report.md}`.

## 6. Known caveats

- Scenario KPIs are analytic (M/M/c) what-if numbers. When a KPI reuses the
  main-chain `path_metrics.json` / `traffic_report.json`, its metadata says
  `source: baseline_main_chain`; it is **not** an independent full simulation.
- Traffic verification is sampled (`dt = 0.05 s`) plus a reservation-table
  replay, not a continuous-time proof.
- JSONL files are written atomically per line by their generators; consumers
  should still skip blank lines.
